# 现场验收

自动化代码检查、隔离复制测试和三台 ARM64 现场验收分别记录。
不要根据容器 healthy 或脚本测试结果把现场步骤填写为 passed。

## 部署前记录

记录每台节点的 CPU 型号、核数、内存、MemAvailable、挂载设备、可用空间、
Docker／Compose 版本、原有服务、网络协商速率和 watchdog 设备／当前持有者。
从路由器核实 VIP 已排除在动态分配范围外，确认局域网可达、VRRP 和端口没有冲突。
保存原有网络规则、业务数据库、Grafana 数据源和客户端配置备份。

## 空集群验收

创建专用验收库与连续编号写入脚本，记录所有成功确认的事务。
分别测试主库停机、当前代理停机、一个 etcd 停机、网络隔离和 watchdog 整机隔离。
每次只引入一个故障，恢复并追平后再执行下一次。
核对新主、VIP、确认事务、同步状态、旧主回归及 timeline。
确认没有合格同步备库时写入等待，恢复同步副本后继续，不能偷偷改成异步。

验证重建、重复部署、备库滚动更新、新节点加入失败重试和并发操作互斥。
在复制和备份时核对 etcd 写入延迟、Patroni 循环耗时和复制积压。

## 资源记录

在相同业务负载下记录部署前后 CPU、整机内存、容器内存、MemAvailable、swap、OOM、
etcd fsync 延迟及数据库复制延迟。覆盖空闲、常规写入、Grafana 查询、备份、恢复和新节点复制。
Docker stats 可能扣除可回收缓存，不能仅用它判断整机内存压力。

## 业务验收

oneMiniHouse：核对完整表、索引、序列、角色、授权及 RLS；使用真实只读身份回归
现有 Grafana 分类、面板和公开页。记录 SQLite 最新一致备份、积压追平和失败回执。
Nexus：核对账号权限、既有镜像 digest、推拉和重启，保存 DB 与 blob 同一停写窗口的备份。

备份目标必须独立于所有数据库节点。恢复演练需要验证结构、角色、权限和数据完整性，
并保存 dump 的 SHA256 与实际恢复结果。首次迁移没有有效恢复证据时不能执行。
